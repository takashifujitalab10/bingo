# 忘年会ビンゴ：GitHub Pages・会場スクリーン版

27人用。会場のスクリーンに大きく映すためのビンゴ抽選アプリです。表示は赤・金・白を基本にしたサンバースト柄です。

## 公開方法

1. この `GitHubPages` フォルダーの**中身すべて**を、GitHubの公開用リポジトリ直下へアップロードします。`index.html` と同じ場所に `assets` / `vendor` フォルダーが必要です。
2. **Settings → Pages** で **Deploy from a branch / main / /(root)** を指定して **Save**。
3. Pagesに表示された **Visit site** のURLから開いてください。

既存サイトを更新するときは、最初にアプリの「参加者・設定 → データを保存」でJSONバックアップを取り、その後で同じ公開先のファイルを置き換えます。見た目が古いままなら Ctrl+F5 で再読込してください。

`index.html` 単体のダブルクリックでは起動しません。今回の公開用版はGitHub PagesなどのHTTP/HTTPSで開いてください。以前のローカル版はZIPの `Previous_Local` 内に保存しています。**Previous_LocalはGitHubへアップロードする必要はありません。**

公式手順：https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

## 会場で使う

- 「参加者・設定」で27人の名前を入力。まとめて貼り付けるときは1行1人です。
- 「全画面」を押してスクリーンに表示します。ブラウザー側で全画面APIが使えない場合はF11キーを使います。
- メイン画面は、左にQRと直近5回の抽選履歴、中央に大きな最新番号、右に次の等級、下に1〜75の番号一覧を表示します。
- 全75番号は5行×15番号の並びです。赤は抽選済み、黄色い背景は最新、灰色は未抽選です。
- 「番号を引く」またはSpaceで抽選。参加者画面で抽選を始めた場合は、自動で番号画面へ戻ります。
- 「参加者チェック」で参加者一覧へ切り替えます。27人の名前・未当選／ビンゴ・等級・順位を確認できます。
- 紙カードを司会者が確認し、該当者のチェックを押して当選を確定してください。自動のカード判定は行いません。
- 確定後に「ビンゴ！」を押すと、直前の当選者の名前・順位・等級を大きく表示し、指定の当選ベルと紙吹雪でお祝いします。表示は「閉じる」まで残ります。
- 当選済みの方は再登録できません。27人全員が当選すると抽選を停止します。

同時に複数人がビンゴした場合は、主催者が順番を決めてから、その順に登録してください。

| 当選順位 | 等級 | 人数 |
| --- | --- | --- |
| 1位 | 1等 | 1人 |
| 2〜3位 | 2等 | 2人 |
| 4〜6位 | 3等 | 3人 |
| 7〜10位 | 4等 | 4人 |
| 11〜27位 | 5等 | 17人 |

## スマホから見る

会場のQRをスマホで読み取ってください。QRをPCでクリックすると大きく表示できます。

スマホの「番号一覧」には最新番号・直近5回の履歴・出た75番号の一覧が出ます。「参加者チェック」で、27人の参加者名・ビンゴ状態・何等が当たったか・順位を確認できます。スマホは閲覧専用です。抽選・当選登録・データの変更はできません。

QRには、その時点の番号と参加者・当選情報を圧縮して含めています。**自動更新がつながらない場合でも、会場の最新QRを読み直せば、その時点の参加者状況まで確認できます。** 情報の更新時刻をスマホに表示します。長い名前が多いとQRが細かくなるため、その場合はQRを大きく表示して読み取ってください。

自動更新はPeerJSの無料接続サーバーとWebRTCを使います。会場のネットワークや端末により、接続できない場合があります。「自動更新中」と「QR読取時点／最終受信時点」を区別して表示します。更新が止まった場合、通常のページ再読み込みだけでは未受信分を取得できないので、最新QRを読み直してください。

司会者PCは、イベント中はブラウザーを開いたままにしてスリープさせないでください。司会者PCを再読込した場合も、必要なら最新QRを読み直します。名前と当選情報はQR／閲覧用リンクを知っている方に表示されます。JSONの完全バックアップや印刷カードはスマホへ送信しません。

## 保存・取り消し・リセット

データは同じPC・同じブラウザー・同じサイトのlocalStorageへ自動保存します。ファイル公開だけでは参加者名は登録されません。名前は公開後のアプリから入力してください。

「データを保存」でJSONに保存、「データを読み込む」で復元します。以前のGitHub Pages版・ローカル版のJSONにも対応しています。URL・ブラウザーを変更した場合は保存データが自動では移らないので、JSONから移してください。

| 操作 | 名前 | 抽選履歴 | 当選記録 | カード |
| --- | --- | --- | --- | --- |
| 抽選・当選結果をリセット | 残す | 消去 | 消去 | 残す |
| 参加者データをリセット | 消去 | 残す | 消去 | 残す |
| すべてリセット | 消去 | 消去 | 消去 | 再生成 |

直前の当選は1人ずつ取り消せます。直前の抽選を取り消すには、その抽選時点で登録された当選者がいない必要があります。必要なら先に当選を取り消してください。

画面の履歴表示は直近5回ですが、抽選済みの全番号は内部データとバックアップへ保持します。

カード印刷も設定画面に残しています。A4縦、9枚×3ページ、27枚を印刷できます。中央はFREEです。「すべてリセット」後はカードが変わるので再印刷してください。

## 検証

- ロジック：27人の等級境界、重複当選防止、75番号の重複なし抽選、直近5回の履歴。
- 共有：日本語の参加者名・27人の当選・75番号を含むQRの生成と復元、不正データの拒否。カード情報は公開スナップショットに含めません。
- ブラウザー：名前入力、6回抽選後の5件履歴、参加者画面への切り替え、当選登録、名前・等級の祝福表示、指定MP3の再生、スマホ閲覧側の27人の状態表示。
- レイアウト：1920×1080 / 1366×768 / 1280×720 / 1024×768 / 1024×600で全75番号がスクロールなしで画面内に収まることを確認。参加者27人の一覧も1024×600で画面内に収まることを確認。
- この検証環境ではPeerJSの端末間接続を確立できなかったため、インターネット経由の自動同期は未確認です。QR読取時点の名前・当選情報の表示は確認済みです。
- 実際の会場スクリーンの視認性・スマホ27台同時の実機接続は未実施です。ブラウザーの全画面APIが制限された検証環境では、指定画面サイズでレイアウトを確認しています。

検証コマンド：`node test.mjs`、`node projection.test.mjs`。
