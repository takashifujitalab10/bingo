# 忘年会ビンゴ（27人用）

GitHub Pagesで使える、ビルド不要のビンゴ抽選アプリです。市販の紙カードにも、付属の印刷カードにも対応します。当選は司会者が手動で登録します。

## GitHub Pagesへの設置

既存のリポジトリを使う場合：

1. このZIPを展開します。
2. リポジトリの `bingo-game` フォルダーを、このフォルダーで丸ごと置き換え、コミット・Pushします。HTMLだけでなく、CSS、MJS、vendorフォルダーも必要です。
3. リポジトリの **Settings → Pages** を開きます。
4. **Source: Deploy from a branch**、**Branch: main**、フォルダー **/(root)** を選んで **Save** します。既に公開済みなら設定を変更する必要はありません。
5. GitHubが表示する公開URLの末尾に `bingo-game/` を付けて開きます。例：`https://ユーザー名.github.io/リポジトリ名/bingo-game/`

新規リポジトリのトップページにしたい場合は、この `bingo-game` の**中身すべて**をリポジトリ直下に配置してください。その場合はGitHubの公開URLをそのまま使います。

ビルド、npm、GitHub Actionsの追加設定は不要です。ローカルファイルのダブルクリックではES Modulesと通信が利用できないため、公開後のURLから開いてください。開発時は静的HTTPサーバーを使います。

公式手順：https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

## 当日の操作

1. PCで公開URLを開きます。「参加者・設定」に27人の名前を入力します。「名前をまとめて入力」なら1行1人で貼り付けられます。名前は入力と同時にこのブラウザーへ保存されます。
2. 音量を調整して「当選ファンファーレを試聴」でスピーカーを確認します。音量が0・効果音オフの場合は音は鳴りません。
3. 「ゲーム進行」の「番号を引く」、または入力欄やボタンにフォーカスがない状態でSpaceキーを押します。1〜75を重複なしで抽選します。
4. ビンゴを申告した方の紙カードを司会者が確認し、名前のチェックボックスを押して「当選を確定」します。カードの自動判定は行いません。
5. 右下の「ビンゴ！お祝い演出」で、直前の当選者名・等級の表示と約4.5秒のオリジナルファンファーレ、紙吹雪が出ます。登録操作と演出は分かれています。繰り返し再生しても当選人数は増えません。
6. 当選済みの方にはチェックが付き、再登録できません。27人全員の当選後は抽選を停止します。

| 当選順 | 景品 | 人数 |
| --- | --- | --- |
| 1位 | 1等 | 1人 |
| 2〜3位 | 2等 | 2人 |
| 4〜6位 | 3等 | 3人 |
| 7〜10位 | 4等 | 4人 |
| 11〜27位 | 5等 | 17人 |

同時に複数の方がビンゴした場合は、じゃんけん等で順番を決めてから、その順に登録してください。誤登録は「直前の当選を取り消す」で1人ずつ戻せます。抽選の取り消しは、その抽選時点で当選者が登録されていない場合のみ可能です。

## スマホで番号履歴を見る

メイン画面のQRをスマホのカメラで読み取ります。閲覧専用画面には最新番号・1〜75の抽選状況・全履歴が出ます。スマホ側で抽選・当選登録・データリセットはできません。

- 自動更新は、PeerJSの無料接続サーバーを使うWebRTCの端末間通信です。追加のアカウント・APIキー・DB設定は不要です。司会者PCとスマホの両方にインターネット接続が必要です。
- 司会者のPCはブラウザーを開いたままにし、スリープさせないでください。共有受付中の接続台数で接続を確認できます。
- 公開接続サーバーの障害、社内ネットワーク、携帯回線のNAT等により、自動更新が接続できない場合があります。PeerJS標準の接続設定を使いますが、専用の中継サーバーは用意しておらず、全回線での接続は保証できません。
- **自動更新できなくても、最新のQRを再度読み取れば、そのQRが表示された時点の全履歴を確認できます。** QRには履歴そのものを埋め込み、抽選・取消・リセットのたびに更新します。
- 「QR読み取り時」「最終受信時点」「自動更新中」を画面に区別して表示します。接続が切れているときにスマホを通常の再読み込みだけで更新しても、未受信分は取得できません。最新QRを読み直してください。
- 名前・当選順位・印刷カードはスマホへ送信しません。QR生成もこのページ内で行い、外部のQR画像APIへURLを送信しません。
- 参加者数27人の機能に対応していますが、27台の実機での同時接続負荷試験は未実施です。当日の会場Wi-Fiと携帯回線で事前に接続を試してください。

PeerJS公式：https://peerjs.com/client/getting-started

## 保存・リセット

名前・抽選履歴・当選記録・印刷カードは、司会者の同じ端末・同じブラウザー・同じURLのlocalStorageに保存します。GitHub上へは保存しません。ブラウザーのデータ削除やPC交換に備え、「データを保存」でJSONバックアップを取ってください。他のPCでは「データを読み込む」で復元できます。バックアップには参加者名を含みます。

| 操作 | 名前 | 抽選履歴 | 当選記録 | カード |
| --- | --- | --- | --- | --- |
| 抽選・当選結果をリセット | 残す | 消去 | 消去 | 残す |
| 参加者データをリセット | 消去 | 残す | 消去 | 残す |
| すべてリセット | 消去 | 消去 | 消去 | 新しく生成 |

リセットには確認画面があります。必要な場合は先にバックアップを保存してください。同じブラウザーで司会者用画面を複数開いた場合、対応ブラウザーでは最初のタブだけを操作可能にします。別PCで同じイベントを同時進行しないでください。

旧たたき台と同じURLで開いた場合、旧 `bingo-names` の名前のみ初回に引き継ぎます。旧版の抽選結果・当選結果・カードは新しい保存形式へ引き継ぎません。旧版で印刷したカードも、今回の手動判定では紙カードとして使えます。

## カード印刷

「カード印刷」でA4縦、9枚×3ページの27枚を用意できます。印刷時は倍率100%・余白はページの設定を使用・ブラウザーのヘッダーとフッターをオフにします。中央はFREE、B/I/N/G/Oの各列はそれぞれ1〜15／16〜30／31〜45／46〜60／61〜75です。印刷後に「すべてリセット」を行うとアプリ内カードは変わるため、必要なら再印刷してください。

## ファイル

- `index.html`：画面
- `style.css`：明るい紫・ゴールドのデザイン、スマホ表示、印刷設定
- `app.mjs`：進行、保存、効果音、QR、番号共有
- `core.mjs`：順位ルール、カード生成、保存形式と共有データの検証
- `vendor/`：同梱ライブラリー（バージョン固定）
- `test.mjs`：`node test.mjs` でロジック検証
- `THIRD_PARTY_NOTICES.md`：依存ライブラリーのライセンス

外部通信はPeerJSの接続サーバー（`0.peerjs.com`）とWebRTC/STUNを使用します。音源・フォント・QRコードは外部CDNへ依存せず、同梱ファイルだけで生成します。

## 検証内容

`node test.mjs` による順位の境界・27人の登録・重複防止・75番号の重複なし生成・共有QRの復元・不正データ拒否の検証は通過しています。Chrome画面で抽選、手動当選、次の景品の切り替え、当選済み操作の無効化、名前保存、参加者リセット、QR読取時点の全履歴表示を確認しました。この開発環境では端末間の自動更新接続を確立できなかったため、実会場でのライブ同期は未確認です。接続に失敗しても最新QRを読み直して履歴を取得できます。
